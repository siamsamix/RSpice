**Problem:** `SimulationResult` carries parallel `Vec`s with no identity, so the same branch-row/column fact is spelled out four times — and the `analysis.rs` copy already rotted: it lost `bjts` the moment BJT/JFET shipped, so `I(Q1)` can never resolve in `.meas`/`.four`, and the GUI's positional `R{i+1}` labels lie on any deck that says `RLOAD`.

**Solution:** results speak the domain language — named branch records and node names travel with the data, `BranchLayout` is the one row-count owner, and every consumer (`gui`, `cli`, `.meas`) resolves by name.

  • locality: the I(Q1) class of bug becomes one module's bug
  • leverage: one interface, three readers already exist
  • deletes MeasCurrents + TranFamily/AcFamily
  • labels survive `RLOAD` renames
  • interface shrinks: node-count dig ×7 collapses

**Problem:** every `.meas`/`.four` operand is re-parsed char-by-char and re-lexed through `eval_num` inside the sample loop, chained through a family copy that also misses Q — because no return path like them was ever drawn.

**Solution:** compile probe operands once at parse into typed bindings — the exact pattern `behavior::ProbeSpec` already proves — and resolve them against the `Circuit` before any sample runs (subsets of candidate 1's named reports provide the values).
